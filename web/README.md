# 八段锦 · Baduanjin — web app

A single-page learning app for the eight Baduanjin movements. Plain HTML/CSS/JS. No build step, no network, no CDN.

## Open it

Double-click `web/index.html`. It runs from `file://`. It reads everything by relative path:

| What | Where (relative to `web/`) |
|---|---|
| Content (moves, steps, key points, outfits, backgrounds, music) | `data.js`, generated from `../Baduanjin/Resources/moves.json` |
| Videos | `../assets/*.mp4` |
| Backgrounds, art icons, thumbnails | `../Baduanjin/Resources/{Backgrounds,Art,Thumbs}/` |
| Music and instrument photos | `../music/tracks/*.mp3`, `../music/pictures/*.jpg` |

## Main page extras

- **Avatar · Background card** (top of the right column): tap an avatar figure to switch outfit, tap a round icon to change the video background. Figures come from `outfits[].avatar`; without one, the move thumbnail is used.
- **Default music** is 高山流水 (High Mountain, Flowing Water, guzheng). Browsers block sound until the visitor interacts, so it starts on the first tap or key press anywhere (taps on the music controls decide for themselves). Choosing silence is remembered.

## Second site: 云手 · Cloud Hands (Tai Chi)

`web/taichi.html` uses the same engine on your own footage in `../../me_video/` (8 Tai Chi moves,
red uniform + qipao, switchable in Scene · Music · Outfit). Its content lives in `data-taichi.js`,
generated by `python3 web/tools/taichi_content.py` (also writes `content/taichi.json`); thumbnails
come from `tools/make_taichi_thumbs.swift` → `content/taichi/thumbs/`. Settings, progress and the
tour-seen flag are stored per site, so the two sites don't share state.

Angles filmed: moves 2–5 front/left/right/back in both outfits; move 1 front/right/back (red) or
all four (qipao); moves 6–8 front only. Step times were read off the clips at ~1 s resolution.

## Third site: 锦影 · Brocade Mirror (Baduanjin, your avatar)

`web/baduanjin-v2.html` plays the eight Baduanjin moves with your own avatar in the deep-red qipao from
`../../me_video/baduanjin-qipao 2/` (the 2026-11-08 consistent-prompt redo), all 4 angles for every move.
The red-uniform set (`../../me_video/v2/baduanjin-uniform/`) was dropped on 2026-11-09 because that avatar
reads heavier than the qipao model; its step times are kept in `v2_content.py` (`RETIRED_CUTS`). With one
outfit, the avatar picker and the drawer's outfit section hide themselves. On every site the first outfit in
the data is the default until the visitor picks one (`outfitPicked` in the saved prefs). Move text is reused
from `moves.json`; only the step times differ (read off contact sheets, ±0.5 s).
`python3 web/tools/v2_content.py` writes `data-v2.js`.

### Brocade Mirror extras (2026-11-09 revamp)

- **One window.** On desktop (≥ 981 px wide, ≥ 600 px tall) the page fills the viewport exactly: the video
  takes whatever height the shorter control panel (~195 px) and the header leave, and the right column
  scrolls inside itself. Phones scroll as before. (`body.fit` in `baduanjin-v2.html`.)
- **Background + music on the main page.** The card at the top of the right column has the 8 backgrounds
  and the music: instrument photos, play/pause, the instrument's tracks, silence and volume. The header
  music dock is gone on this site.
- **Music loads at start.** The default track (高山流水) is preloaded and started on load; browsers that
  block sound until you interact start it on the first tap.
- **Breathing cue.** A glass ring with 吸 / 呼 / 停 inside, an arc that fills over the step, and a countdown
  ("2 s · step 3/4") at the current speed. All three sites have it.
- **Onboarding** (`js/journey.js`, first visit, or open the page with `?onboarding`): sign in → why you want
  to learn → level → time per day / days per week / plan length → reminders → benefits + testimonials +
  plan chart → feature showcase (live demos of the 4 angles, speed, backgrounds, music, mirror/zoom,
  breathing cue) → your plan and first week. Content (goals, levels, testimonials, research note) lives in
  `v2_content.py` (`JOURNEY`). **The three testimonials are sample text** and are labelled "Sample" on the page;
  replace them with real quotes (and drop `sample`) when you have them.
- **My progress** (header pill, shows today's minutes vs your daily goal): today / this week / streak /
  mastered tiles, a 14-day minutes chart with the daily goal line (hover for values, "Table view" for the
  numbers), the eight moves, your plan, and reminder settings. Practice time is real playback time per day,
  stored in `localStorage` (`P.days`).
- **Reminders.** In-page reminders fire while the page is open (browser notification if allowed, otherwise
  an in-app card). "Add to calendar" downloads a repeating `.ics` event with an alarm, which works when the
  page is closed. There is no push server.

### Sign-in (Google, Apple, phone number)

The buttons are wired to the real providers, configured in `v2_content.py` (`AUTH`):

| Provider | What to fill in | Where to get it |
|---|---|---|
| Google | `googleClientId` | Google Cloud console → Credentials → OAuth client ID (Web), with the site's https origin authorised |
| Apple | `apple.clientId`, `apple.redirectURI` | Apple Developer → Identifiers → Services ID with Sign in with Apple, domain + return URL verified |
| Phone (SMS) | `firebase` (the web app config object) | Firebase console → Authentication → Phone enabled, the site's domain authorised |

Providers only work when the page is served over **https** (or `localhost`); from `file://` or with an empty
value, the button explains that and offers "Continue on this device", which saves a local profile (and the
phone number, unverified) in `localStorage`. Tokens are not verified server-side, and nothing syncs between
devices yet; that needs a backend.

### 问一问 · Ask (TypeSafe AI)

Header pill **Ask**: a chat about Baduanjin benefits, modifications (knees, back, neck, shoulders, seated,
balance, blood pressure, pregnancy, osteoporosis, hips…) and things to keep in mind (breathing, timing,
pain, when to stop, when to see a doctor), plus benefits / technique / adaptations for each move.

- TypeSafe's model **Jev does not write text**; it answers typed questions with calibrated probabilities.
  So every reply is one of 61 pre-written answers in `tools/ask_content.py` (37 general + 3 per move from
  `moves.json`), written in Chinese and English. Jev picks the answer (one Choice over all 61), and three
  yes/no checks decide how to show it: does any answer fit, is the question on topic, and does it describe
  urgent symptoms (then the "stop and get help" answer is shown first). Low-fit questions get "I don't have a
  prepared answer for that yet"; off-topic ones are declined. Answers can't be invented. The answers were drafted by Claude from `moves.json` and `taichi_knowledge/`;
  have a qualified teacher review them.
- `python3 tools/ask_content.py` rewrites `data-ask.js` + `content/ask.json` after editing answers.
- **The API key never reaches the browser.** `tools/ask_server.py` (run by `sh serve.sh`) serves the site
  and `POST /api/ask`; it reads the key from `$TYPESAFE_API_KEY` or `~/.config/brocade-mirror/typesafe.key`
  and builds the TypeSafe request itself, so the page can only send a question. See "Local helper and
  security" below: only pages it serves itself may call it, so from `file://` the chat uses offline matching.
- Without the helper, the chat still works with a local keyword match (status line says "Offline matching").
- `python3 tools/ask_eval.py` runs 28 live cases (zh/en, follow-ups, off-topic, urgent) against the helper:
  28/28 on 2026-11-10, about 150–300 ms per question.
- Analytics: `ask_opened`, `ask_question` (answer id, source, fit bucket; never the question text).

### Voiceover and voice coach (Deepgram)

- **Voiceover** (toggle next to Loop / Step pause / Cues): each step is narrated as it starts, opening with
  the breath ("Breathe in…"). If the narration is still going when the step ends, the video waits for it, so
  the words always match the picture (at 1× most steps are shorter than their narration; 0.5–0.75× flows
  better). The first time a move is opened with voiceover on, its explanation plays (name, purpose,
  benefits, breathing). The full routine announces each move. Music ducks while it speaks.
  English clips are pre-generated with Deepgram Aura-2 (`aura-2-athena-en`) by `python3 tools/voice_content.py`
  into `content/voice/en/` (48 clips, 2.4 MB, included in the one-file build), so voiceover needs no network.
  **Deepgram has no Chinese voice**: in Chinese the system voice (Tingting on macOS) reads the same text.
- **Voice commands** (header pill **Voice** → Voice commands): hands-free. It listens, detects the end of each utterance, sends it
  to the helper (`POST /api/stt` → Deepgram nova-3, English or Chinese by UI language) and then either runs a
  command or asks 问一问 and reads the answer aloud (`POST /api/tts` → Deepgram Aura-2, cached in
  `~/.cache/brocade-mirror/tts`; Chinese via the system voice). It doesn't listen while it is speaking.
  Commands: play / pause / again, slower / faster / normal speed / half speed, next / previous move,
  "move 3" / "third move" / 第三式, full routine, mirror, front / left / right / back view, four angles,
  explain (this move), voiceover on / off, stop listening; Chinese equivalents (暂停, 慢一点, 下一式, 镜像, 左侧, 讲解…).
  Longer sentences are treated as questions, so "can I continue with bad knees?" goes to Ask.
- The coach needs the helper and the microphone, which browsers only allow on `http://localhost` (or https):
  run `sh serve.sh` and open http://localhost:8765/web/baduanjin-v2.html. From `file://` the Coach button
  explains this. Chinese is detected from the words spoken, not the UI language. Deepgram key: `$DEEPGRAM_API_KEY` or `~/.config/brocade-mirror/deepgram.key`.
- Analytics: `voiceover_toggled`, `voiceover_explain`, `coach_started` / `_stopped`, `coach_command`,
  `coach_question` (no transcripts).

### AI instructor (Vapi): spoken questions during a workout

Header pill **Voice** → **AI instructor**. A live voice conversation (Vapi web call) while you practise: ask
"am I supposed to breathe in here?", "slow it down", "go to move five", "show me the side view", "my knee
hurts". It knows the eight moves, the step you are on, your plan and the 问一问 library, and it controls the
player through tools (play / pause / restart, speed, go to move, view angle, mirror). Safety rules are in the
prompt: stop and seek help for chest pain, dizziness, sharp pain; no diagnosis.

- English: Claude Haiku 5.5 brain, Deepgram Aura-2 voice (athena), Deepgram nova-3 transcription.
  Chinese (when the UI is in Chinese): Azure `zh-CN-XiaoxiaoNeural` voice, nova-2 zh-CN transcription.
- The page uses Vapi's **public** key (`VAPI` in `tools/v2_content.py`, like a PostHog `phc_` key); it can
  only start web calls with the assistant defined in `js/instructor.js`. Restrict it to your domains in the
  Vapi dashboard before going live. Calls are billed to the Vapi account per minute.
- Needs the microphone, so open it from http://localhost:8765 (or https). The Web SDK (@vapi-ai/web 3.1.0,
  MIT) is bundled in `vendor/vapi.js` and loaded only when the instructor starts.
- The card shows the live transcript, Mute and End. Analytics: `instructor_started` / `_ended`,
  `instructor_tool` (tool name only; no transcripts).

### Learning path and research sources (Exa)

My progress → **My learning path**: three stages, Foundations (weeks 1–2) → Flow (3–6) → Refine (7+), each with
steps and a daily routine. The starting stage comes from the onboarding level and moves up as moves are marked
mastered (4 → Flow, 8 → Refine). Your goals pick moves to emphasise (stress → 1 and 5, balance → 2, 5, 8…).
**Adapt for** chips (knees, lower back, neck, shoulders, balance / older, seated, blood pressure / heart,
pregnancy, osteoporosis) show the easier variations from 问一问 with sources.

- Sources: `python3 tools/exa_content.py` searches Exa within reputable domains only (NIH / PubMed / PMC,
  MedlinePlus, Mayo, Cleveland Clinic, Johns Hopkins, Harvard Health, NHS, CDC, WHO, ACOG, arthritis charities,
  open-access journals) and writes `content/refs.json` + `data-refs.js`: 3 per level, 3 per modification
  topic (42 total, $0.13). Results were screened by hand; off-topic ones go in `SKIP_URLS`. The 问一问 chat
  shows two of them under modification answers.
- **Find more research for my plan** searches Exa live through the helper (`POST /api/refs`, built from your
  stage, goals and adapt chips; same domain list). Key: `$EXA_API_KEY` or `~/.config/brocade-mirror/exa.key`.

### Local helper and security

`sh serve.sh` runs `tools/ask_server.py` on 127.0.0.1:8765. It serves `baduanjin_app/` and `../me_video/`
(the Brocade Mirror videos, at `/me_video/`) and holds every secret key; the page only ever sends questions,
audio or form fields. It only answers requests whose Host is `localhost:8765` / `127.0.0.1:8765` and whose
Origin is that same page (so other websites, other local ports, DNS rebinding and `file://` pages can't use
your keys); POSTs must be JSON with a sane Content-Length; dotfiles and directory listings are refused;
60 API calls a minute. Secret keys live in `~/.config/brocade-mirror/` (typesafe, deepgram, exa, resend,
stripe `.key`, chmod 600), **never inside `baduanjin_app/`**, because the one-file build embeds this folder.
Keys that are meant to be public (PostHog `phc_`, Vapi public key) are in `tools/v2_content.py`.

The **full routine has all 4 angles and the 4-angle grid**: `tools/make_v2_media.swift` joins each

This wraps the JSON as `window.BDJ = …`, because `fetch()` of local JSON is blocked on `file://`. Don't edit `data.js` by hand.

## Features

- **Two modes**
  - **Learn a move** (单式精学): the 8 single-move clips.
  - **Full routine** (全套跟练): the whole ~10-minute set. It has a chapter timeline and a chapter list with thumbnails, and the panel follows the move currently playing.
- **Step breakdown**
  - The timeline is split into the move's steps and colour-coded by breath: celadon = inhale, sand = exhale, gold = hold.
  - A caption bar under the video shows the current step.
  - The step list highlights in sync with playback and shows a progress bar.
  - Tap a step to jump to it. Tap ↻ to loop that step.
- **Breathing cue**: a ring on the video expands on 吸, contracts on 呼, and holds on 停. It follows video time, so it slows down with the speed slider.
- **4 camera angles** (Front / Left / Right / Back) plus a synchronised **4-angle grid**. Angles the footage lacks are disabled (struck through), never broken. In the grid, a missing angle shows a "no footage" tile.
- **Speed slider** from 0.25× to 2× (`[` `]`, `=` resets to 1×).
- **Pause**, step back/forward, and frame-by-frame (`,` `.`).
- **Loop modes**: whole clip, single step (or single movement in the full routine), A–B loop, and off.
- **Step pause** (逐步停): stops automatically at the end of each step.
- **Zoom**: presets per move from `moves.json` `focus` (e.g. Hands, Horse stance, Heels), a zoom slider, drag-to-pan, ctrl/pinch-wheel zoom, and double-click to reset.
- **Mirror** mode, so left and right match you when you follow along facing the screen.
- **Text instruction** tabs: Steps, Key points (要领), Common mistakes with fixes (易错), and Benefits / breathing / caution (功效).
- **Scene drawer** (布景 · 音乐 · 服装):
  - **Outfit**: red training suit (10 s clips, multiple angles) or sportswear (75 s follow-along, front only; steps become text-only).
  - **Background**: Original plus 7 painted scenes, replaced live (see below).
  - **Music**: instrument cards with photos (guzheng, pipa, dizi/xiao, erhu, ensemble) and a track list. The selected track loops; "Play all" plays the instrument's tracks in sequence. Switching tracks fades out and in, and there is a volume slider.
  - The video's own ambient audio is muted by default, with a toggle.
- **Chinese / English** toggle for the whole UI and all content. The first visit defaults to the browser language.
- **Progress**: a self-rating per move (未学 / 初学 / 练习中 / 已掌握), a practice-rep counter, and a "mastered x / 8" count. Stored in `localStorage` together with your preferences.
- **Keyboard shortcuts**: Space, ← →, `[ ]`, `=`, `, .`, L (loop), P (step pause), M (mirror), Z (zoom focus), G (grid), A/B, C (cues), 1–8 (move), F (fullscreen), ? (help).
- Responsive layout: video on the left and the learning panel on the right on desktop, stacked on phones. Fullscreen shows the step caption over the video.

Music credits are listed in the help dialog (?).

## How background replacement works

The footage is a person on a white/light-grey studio backdrop. The app keys the backdrop out in real time on your device. Nothing is uploaded or pre-rendered. Code: `js/compositor.js`.

The page chooses a back-end when the first video loads:

1. **WebGL shader** is used when the browser lets the page read video pixels: Safari/WebKit on `file://`, or any browser when the folder is served over http (`python3 -m http.server` inside `baduanjin_app/`). The person is drawn to a transparent canvas over the chosen background image. The shader:
   - treats low-saturation, bright pixels as backdrop, using soft ramps;
   - uses stricter ramps on the floor area, where the glossy floor reflects the red suit;
   - shrinks the edge by 1 pixel, and about 2 pixels on the softer full-routine and sportswear encodes;
   - removes light halo pixels on the silhouette edge;
   - subtracts the grey backdrop out of edge pixels (spill), so there is no white rim on dark scenes;
   - **shoe fill**: white shoes on a white floor are the same colour as the backdrop. In the floor zone, a pixel is kept if there is suit above it (within 7 % of frame height) and a tan shoe sole below it (within 3 %, near the bottom of the frame). This restores the shoes without filling the gaps between the legs.
2. **SVG filter**: Chrome and Firefox treat every `file://` file as a separate origin, so WebGL/canvas may not read the video. In that case the same key is applied with `filter: url(#bdjKey)` on the `<video>` element. CSS/SVG filters never expose pixels to script, so they are allowed on `file://`. It is built from `feColorMatrix`, `feComponentTransfer`, `feMorphology`, `feOffset` and `feImage`, and includes the floor thresholds and the shoe fill, but not the spill subtraction.

"Original" turns the processing off. Zoom and mirror are CSS transforms on the composited layer, so they work in both back-ends.

**Why not MediaPipe segmentation?** On `file://`, Chrome blocks both loading the ES-module/wasm bundle and the pixel reads that segmentation needs. On this clean studio footage, a colour key gives crisper edges than the 256×256 lite pose mask anyway.

**Known limits**
- Small artefacts can appear at the feet: a faint pink floor-reflection haze between the shoes, occasional thin hatching beside the knees when zoomed in close, and imperfect shoe edges.
- The full-routine and sportswear videos are low-bitrate, so their edges are a little softer.
- The SVG mode could only be verified in WebKit here (no Chromium on this machine). In WebKit, only the first element using a shared SVG filter rendered, which would affect the 4-angle grid if WebKit ever used SVG mode. WebKit uses the WebGL path, so this does not come up in practice, but SVG mode in Chrome is unverified.
- The 4-angle grid runs 4 videos plus 4 keyers, which is heavier on low-end machines.

## One-file version (everything included)

`../Baduanjin-standalone.html` (~300 MB; `../BrocadeMirror-standalone.html` ~365 MB, `../TaiChi-standalone.html` ~500 MB) has all code, images, videos and music inside. It runs anywhere, even copied alone to another Mac or a USB stick. Rebuild it after changing the app: `python3 web/tools/build-standalone.py`.
